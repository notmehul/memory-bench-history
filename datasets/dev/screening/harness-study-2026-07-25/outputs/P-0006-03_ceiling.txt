# Design Doc Requirement for Multi-Service Changes

A design doc is mandatory when a proposed change touches **three or more services**.

In plain terms: if the work affects **1 or 2 services**, a design doc is not required by this policy; if it affects **3 or more services**, you must write one before implementation.

Example: if a change updates the API gateway, the billing service, and the notifications service, the change touches **3 services**, so a design doc is required.
